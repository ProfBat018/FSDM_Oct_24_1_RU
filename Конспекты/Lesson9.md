# Тема урока: Memory Management in C#

Еще начиная с С++ мы с вами изучали построение работы памяти во время выполнения программы. Как мы знаем, у любой программы выполняемой нашей операционной системой есть стек и куча. Давайте углубимся в эту тему и посмотрим, как это работает в C#.

## Stack

`Stack` - это область памяти, которая фиксируется вашей операционной системой для хранения данных для быстрого доступа. На одну программу выделяется столько `Stack`-ов, сколько потоков в этой программе.
`Stack` работает по принципу LIFO (Last In First Out), то есть последний добавленный элемент будет первым удалённым.

В C# вы можете написать `unsafe` код, который сможет сделать аллокацию памяти в стеке с помощью ключевого слова `stackalloc`. Однако, это не рекомендуется делать, так как это может привести к утечкам памяти и другим проблемам. Вот пример использования `stackalloc`:

```csharp
unsafe
{
    int* numbers = stackalloc int[10];
    for (int i = 0; i < 10; i++)
    {
        numbers[i] = i;
    }

    for (int i = 0; i < 10; i++)
    {
        Console.WriteLine(numbers[i]);
    }
}
```

## Heap

`Heap` - это область памяти, которая используется для хранения объектов и данных. В отличие от `Stack`, `Heap` не имеет фиксированного размера и может расширяться по мере необходимости. В C#, у нас есть `Managed Heap`, который управляется `CLR` (Common Language Runtime).

- **Large Object Heap (LOH)**: Это область памяти, которая используется для хранения больших объектов (обычно более 85 КБ). LOH управляется отдельно от обычного кучи и может иметь свои собственные правила сборки мусора.
- **Small Object Heap (SOH)**: Это область памяти, которая используется для хранения небольших объектов (обычно менее 85 КБ). SOH управляется сборщиком мусора и имеет свои собственные правила сборки мусора.
- **Pinned Object Heap**: Это область памяти, которая используется для хранения объектов, которые не могут быть перемещены сборщиком мусора. Это может быть полезно, когда вы работаете с небезопасным кодом или с кодом, который использует указатели.

- **Поколение 0**: Это начальное поколение, в которое помещаются новые объекты. Когда память заканчивается, происходит сборка мусора (Garbage Collection), и объекты, которые больше не используются, удаляются.
- **Поколение 1**: Если объект пережил сборку мусора в поколении 0, он перемещается в поколение 1. Это означает, что объект используется дольше и, вероятно, будет использоваться и дальше.
- **Поколение 2**: Если объект пережил сборку мусора в поколении 1, он перемещается в поколение 2. Это означает, что объект используется очень долго и, вероятно, будет использоваться и дальше.

Все эти три поколения хранятся в `SOH`.

## Garbage Collection

`Garbage Collection` (GC) - это процесс автоматического управления памятью в C#. Он отвечает за освобождение памяти, занятой объектами, которые больше не используются. GC работает по принципу отслеживания объектов и их ссылок, чтобы определить, какие объекты можно удалить. Для того чтобы понять, какие объекты можно удалить, GC использует алгоритм "маркировки и удаления". Те объекты, которые не имеют ссылок на себя, считаются "мусором" и маркируются для удаления. Также маркировка поисходит для тех элементов, которые не используются в текущий момент. Также методом дифференциального сравнения, GC определяет какие объекты увеличились в объёме и какие объекты уменьшились в объёме. Потом он перенесет эти объекты в новое поколение, а старые объекты, которые не были изменены, останутся в старом поколении.

GC работает в фоновом режиме и может запускаться в любое время, когда система считает это необходимым. Вы можете вызвать сборщик мусора вручную с помощью метода `GC.Collect`, но с выходом из Framework в Core у вас не получится вызвать сборщик мусора вручную, так как это не рекомендуется делать.

# ВАЖНО!

Сборщик мусора можно вызвать также через операционную систему, как это делается в DotMemory

Кроме всего этого в C# есть несколько очередей для управления памятью:

- **Finalization Queue**: Это очередь, в которую помещаются объекты, которые имеют метод `Finalize`. Этот метод вызывается перед удалением объекта сборщиком мусора. Он позволяет выполнить очистку ресурсов, которые не могут быть освобождены автоматически.
- **Pinned Object Queue**: Это очередь, в которую помещаются объекты, которые не могут быть перемещены сборщиком мусора. Это может быть полезно, когда вы работаете с небезопасным кодом или с кодом, который использует указатели.
- **Weak Reference Queue**: Это очередь, в которую помещаются объекты, на которые есть слабые ссылки. Слабые ссылки позволяют сборщику мусора удалять объекты, на которые нет сильных ссылок.

Из мега интересного, что в C# есть value-type-blob в Heap. Мы с вами проходили boxing и unboxing, когда мы преобразуем value type в reference type и наоборот. Так вот при boxing происходит создание value-type-blob в Heap, который содержит значение value type. Это позволяет сборщику мусора управлять памятью более эффективно, так как он может удалять value-type-blob, когда они больше не используются.

Для того чтобы хранить `static` данные в C#, используется `High Frequency Heap`. Это область памяти, которая используется для хранения статических данных, таких как константы и статические поля.
