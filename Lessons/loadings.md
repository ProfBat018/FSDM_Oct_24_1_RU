# Тема урока: Типы объединений в EF Core

- Lazy Loading
- Eager Loading
- Explicit Loading

# Lazy Loading

Данный тип объединения уже старый и не используется. На это есть ряд причин.

1. Lazy Loading подгружает данные при обращении к навигационному свойству все данные, даже те которые не нужны.
2. Он работает неявно, что противоречит принципам императивного программирования.

### Что такое навигационное свойство ?

Предположим у нас есть класс:

```csharp
class Person
{
    public string Id {get; set; }
    public string Name {get; set;}
    public string Surname {get; set;}
}

class Student
{
    public string Id {get; set;}
    public string FacultyName {get; set;}

    [ForeignKey]
    public string PersonId {get; set;}

    // нужен чтобы удобно подружать данные
    public Person Person {get; set;}
}
```

При обращении в DbSet, который находтся внутри DbContext, мы будем просто обращаться к данному навигационному свойству.

```csharp

using var context = new UserDbContext();

var res = context.Students.Where(x => x.Person.Name == "Elvin");
```

но чтобы код сверху работал, а не возаращал мне NullReferenceException, нам с версии dotnet какой именно я не помню но уже давно, нужно подключать библиотеку **Microsoft.EntityFrameworkCore.Proxies**

Проблема Lazy Loading в том, что он подгрузит роли абсолютно всех пользователей в таблице даже если вы сделали фильтрацию с Where. Иначе он работать не умеет. В целом данный способ подрузки данных работает медленно и его использовать я вам не рекомендую.

# Eager Loading

Eager Loading — это механизм, при котором связанные данные подгружаются **сразу**, во время выполнения запроса. Это делается явно с помощью метода `.Include()`.

Пример:

```csharp
using var context = new UserDbContext();

var roles = context.UserRoles
    .Include(ur => ur.User)
    .Include(ur => ur.Role)
    .Where(ur => ur.User.Name == "Elvin")
    .Select(r => r.Role.Name)
    .ToQueryString();

```

Преимущество Eager Loading:

- Вы заранее указываете, какие данные нужны.
- Работает быстрее, чем Lazy Loading, так как делает **один SQL-запрос с JOIN**.
- Предсказуемое поведение.

Недостатки:

- Загружает больше данных, если вы `Include` используете без нужды.

# Explicit Loading

Explicit Loading — это **явная** подгрузка навигационного свойства **после** основного запроса, вручную через метод `.Entry().Reference().Load()` или `.Entry().Collection().Load()`.

Пример подгрузки навигационного свойства:

```csharp
using var context = new UserDbContext();

var student = context.Students.First(x => x.Id == "some-id");

context.Entry(student)
    .Reference(x => x.Person)
    .Load();
```

Также можно загрузить коллекцию, если, например, `Person` имеет множество `Students`:

```csharp
using var context = new UserDbContext();

var person = context.Persons.First(p => p.Id == "some-id");

context.Entry(person)
    .Collection(p => p.Students)
    .Load();
```

Таким образом, вы вручную подгружаете связанные записи из таблицы `Students`, у которых внешний ключ указывает на этого `Person`.

Преимущества:

- Полный контроль над подгрузкой.
- Можно решить, когда и что именно подгружать.

Недостатки:

- Два отдельных запроса в базу данных.
- Может быть менее эффективно, если вам нужно сразу много связанных сущностей.

# Когда что использовать?

| Тип загрузки        | Когда использовать                                                                                                                                 |
| ------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| ❌ Lazy Loading     | Лучше избегать. Используется только в наследии или для простых одноразовых моделей.                                                                |
| ✅ Eager Loading    | Когда вам **сразу нужны** связанные данные и вы хотите **оптимизировать запрос**.                                                                  |
| 🔁 Explicit Loading | Когда вы хотите **подгружать данные вручную**, **в условиях динамики или интерактивности** (например, при навигации между экранами или разделами). |

---

### Резюме:

- **Используйте Eager Loading**, если точно знаете, что связанные данные понадобятся сразу.
- **Используйте Explicit Loading**, если данные нужны _только иногда_, и вы не хотите перегружать запрос.
- **Не используйте Lazy Loading**, если только вы не уверены в его необходимости и последствиях (например, множественные скрытые SQL-запросы).
